# Subgroup MAP Formalization Note

## Scope

The note compares the supplied FaialAA paper with the current local Faial
implementation and then states the subgroup/matrix extension in the same style
as Memory Access Protocols. The supplied PDF is
`/Users/zheyuan/GPU-DRF/3689797.pdf`, which presents the FaialAA analysis and
restates the MAP formalization used by Faial. Paper claims below cite the PDF
page and section. Implementation claims point to local OCaml modules.

The note has one narrow purpose. The original MAP proof model treats a
synchronization-free workgroup phase as the unit of race checking. The local
extension keeps that model for ordinary kernels and adds a second ordering
layer for subgroup barriers, together with participation checks for subgroup
and matrix collectives. The extension does not claim arbitrary CUDA support,
direct warp lockstep semantics, or a new Coq theorem.

### Semantic Target

The subgroup DRF model separates collective participation from memory
ordering. Recognized shuffles, reductions, ballots, and matrix collectives are
subgroup participation events, but they do not advance a memory phase.
Explicit subgroup barriers such as full-mask `__syncwarp` advance the subgroup
phase according to their documented memory semantics, while never ordering
different subgroups.

## Original MAP Model In The Supplied Paper

MAPs model memory locations rather than values. The paper describes one
protocol per array and uses symbolic binders for unknown values, including
unknown reads, symbolic loop bounds, and kernel parameters (PDF pp. 5-8,
Sections 2.1 and 3.1).

The protocol grammar used by the paper is:

```text
p ::= var x. p
    | o[e]
    | skip
    | p ; p
    | if c { p } else { p }
    | for x in e .. e { p }

o ::= rd | wr
```

The action generated by an access is an access value:

```text
i : o[e]
```

`i` is the executing thread, `o` is the access mode, and `e` is the array
index. The dynamic semantics maps a protocol, thread identifier, and phase into
a trace and a phase of access values (PDF p. 8, Figure 3). The paper gives
standard rules for access, sequencing, conditionals, loops, and symbolic
binders.

Synchronization is intentionally absent from the protocol grammar. The paper
states that synchronized protocols are split into synchronization-free
protocols and each synchronization-free protocol is checked independently (PDF
p. 7, Section 3.1). The synchronized source language in Section 4 also
separates synchronized statements from unsynchronized fragments. Memory
accesses appear in unsynchronized fragments, while barriers delimit the
fragments (PDF pp. 11-13, Section 4.1).

The paper defines a data race as two actions in the same trace that access the
same array index, come from different threads, and have at least one write (PDF
p. 16, Section 4.3):

```text
race(a1, a2) =
  a1 = (i : o1[k], t)
  a2 = (j : o2[k], t)
  i != j
  write(o1) or write(o2)
```

FaialAA then reasons about approximation sources. Control independence (CI)
means symbolic variables do not affect the trace shape. Data independence (DI)
means symbolic variables do not affect array indexes. CIDI protocols have both
properties (PDF pp. 9-11, Section 3.2). The paper proves that CIDI alarms are
true positives through the True Positive Theorem (PDF p. 16, Theorem 4.5).
The supplied paper also states that the mechanization includes the MAP
determinism, inference soundness, action-set correspondence, and true-positive
results (PDF p. 16, Section 4.4).

The implementation discussion in the supplied paper lists original Faial
support for CUDA features such as multi-dimensional thread identifiers,
multi-dimensional arrays, block synchronization, shared/global memory, and
same-block or same-warp race candidates (PDF p. 16, Section 5). Same-warp race
classification is not the same as modeling warp operations as synchronization
or cooperative matrix operations. The local extension below adds that missing
logical layer.

## Local Ordinary Faial Model

The ordinary local pipeline still follows the original MAP shape:

```text
Protocols.Kernel
  -> Wellformed
  -> Aligned
  -> Phasesplit
  -> Locsplit
  -> Flatacc
  -> Symbexp
  -> Z3
```

`faial/drf/README.md` documents the stages. The important semantic boundary is
`Flatacc -> Symbexp`. After phase splitting and location splitting, each
ordinary proof obligation is a two-thread formula over one array in one
workgroup phase.

The current implementation also exposes that boundary through
`drf/lib/memory_event.ml`. For ordinary kernels, an access event is:

```text
e_ord =
  < id, workgroup_phase, mode, location, index,
    source_guard, runtime_condition >
```

For a pair of ordinary events in the same location phase, the proof obligation
has the shape:

```text
obligation_ord(e1, e2) =
  distinct_thread(task1, task2)
  and source_guard_1(task1)
  and source_guard_2(task2)
  and runtime_condition_1(task1)
  and runtime_condition_2(task2)
  and same_index(index_1(task1), index_2(task2))
  and conflict(mode_1, mode_2)
```

Z3 proves DRF for the obligation when the formula is unsatisfiable. A satisfying
model is a concrete race witness for that obligation. Unknown and timeout
results are not accepted as DRF.

## Subgroup And Matrix Extension

The local extension adds source-level subgroup and matrix sites before the DRF
solver sees proof obligations. The source dispatch lives in
`inference/lib/subgroup_source.ml`. The subgroup/matrix IR lives in
`inference/lib/subgroup_matrix.ml`. The DRF event boundary and obligation
generation live in `drf/lib/memory_event.ml`. Uniformity checking lives in
`drf/lib/subgroup_uniformity.ml`.

### Target Configuration

Subgroup semantics require an explicit target configuration:

```text
cfg = cuda_x_contiguous(subgroup_size)
```

For CUDA-like kernels, the current supported mapping is:

```text
same_subgroup_cfg(i, j) =
  i.threadIdx.y = j.threadIdx.y
  and i.threadIdx.z = j.threadIdx.z
  and floor(i.threadIdx.x / subgroup_size)
      = floor(j.threadIdx.x / subgroup_size)
```

`Inference.Subgroup_matrix.Target_config.same_subgroup` implements this
predicate. Missing subgroup size is an error for subgroup or WMMA kernels. The
analysis does not infer a lane mapping from CUDA source text.

### Extended Event Language

The extension keeps workgroup phases and adds subgroup phase keys. A subgroup
phase key is the ordered list of memory-ordering subgroup barrier site ids that
have occurred since the current workgroup phase began:

```text
W in Nat
S in SiteId*
phase = (W, S)
```

A workgroup barrier with memory semantics increments `W` and resets the
subgroup key. A subgroup barrier with memory semantics appends its site id to
`S`. Collective and matrix sites remain in the event stream for participation
checking, but leave `(W, S)` unchanged. The implementation records these
phases in `Memory_event.Subgroup_event.Phase`. These keys encode ordering for
non-repeating sites; they are not dynamic invocation identifiers.

The extended event language is:

```text
e ::= mem(origin, location, condition, W, S, site_order, cfg)
    | boundary(kind, site, condition, W, S, cfg)

origin ::= ordinary_read
         | ordinary_write
         | ordinary_atomic

kind ::= workgroup_barrier
       | subgroup_barrier
       | subgroup_collective
       | matrix_collective
```

Only memory events become DRF obligations. Boundary events update the phase key
and become uniformity obligations when they are subgroup or matrix operations.

### Implemented Subgroup Ordering

The original MAP model treats a workgroup barrier as a phase boundary. The
extension introduces a subgroup-local ordering predicate inside a workgroup
phase.

For nonrepeating sites, the implementation uses the following rule for two
conditional accesses `a` and `b`:

```text
not_ordered_by_subgroup_cfg(a, b) =
  if subgroup_phase(a) = subgroup_phase(b)
  then true
  else not same_subgroup_cfg(task1, task2)
```

`Memory_event.Subgroup_obligation.not_ordered_by_subgroup_condition`
implements the predicate. The rule has two consequences.

1. Two accesses in the same subgroup phase are unordered.
2. Two accesses separated by a memory-ordering subgroup barrier are ordered
   only when the two projected tasks are in the same subgroup.
Different subgroups remain unordered. Neither a subgroup barrier nor a WMMA
operation is promoted into a workgroup barrier, and a WMMA operation does not
itself advance the subgroup phase.

This rule is the intended subgroup DRF semantics. The uniformity obligation
checks that a collective's required lanes participate in the same dynamic
instance; it does not turn that collective into a memory-ordering operation.

### Repeated Barrier Sites

A static site id cannot distinguish loop iterations. Source extraction marks a
site as `may_repeat` whenever it occurs in a `for`, `while`, or `do-while`
condition, body, or increment. The subgroup phase encoding therefore does not
classify a repeated memory-ordering barrier by static site alone. Instead, the
subgroup route also retains Faial's aligned loop protocol and uses its memory
verdict for this case. The aligned protocol preserves loop structure and does
not merge executions from different iterations.

For a repeated workgroup barrier, this recovers Faial's ordinary loop-aware
ordering. For a repeated subgroup barrier, the fallback omits subgroup-local
ordering; this is conservative and can report a potential race that the scoped
phase encoding could discharge. Participation remains checked by the subgroup
uniformity analysis in both cases.

Missing target facts and other unsupported boundaries remain inconclusive;
only the repeated memory-ordering-barrier boundary invokes the loop protocol.

### Subgroup Memory Race Obligation

The subgroup memory obligation extends the ordinary two-thread race formula
with invocation-domain facts and subgroup ordering:

```text
obligation_subgroup(a, b) =
  invocation_domain(task1, task2, block_dim)
  and distinct_thread(task1, task2)
  and condition_a(task1)
  and condition_b(task2)
  and same_location(location_a, location_b)
  and footprint_overlap(footprint_a(task1), footprint_b(task2))
  and conflict(mode_a, mode_b)
  and not_ordered_by_subgroup_cfg(a, b)
```

The implementation groups candidate pairs by workgroup phase and by memory
location. Candidate generation is in
`Memory_event.Subgroup_obligation.obligations_of_phased`. `Access.can_conflict`
filters pairs that cannot race by access mode.

Z3 receives one obligation at a time. Unsat means no race exists for that
obligation under the supplied source, launch, and target facts. Sat means the
formula contains a race witness. Timeout or unknown remains inconclusive.

### Subgroup Uniformity Obligation

The memory formula alone does not justify calling a subgroup operation. The
extension adds a separate uniformity judgment:

```text
cfg, U |- condition is subgroup_uniform
```

`U` is the set of variables known to be subgroup-uniform. The implementation
classifies CUDA-like variables as follows.

```text
uniform:
  blockIdx.*
  blockDim.*
  gridDim.*
  threadIdx.y, threadIdx.z under x-contiguous subgroup mapping
  threadIdx.x / subgroup_size when divisor matches cfg.subgroup_size
  variables explicitly recorded as uniform

nonuniform:
  threadIdx.x
  threadIdx.x % n
  lane, lane_id, subgroup_lane
  unknown calls
  variables produced by subgroup operations unless explicitly justified
```

Every subgroup barrier, subgroup collective, and matrix collective site must be
under subgroup-uniform control. `Subgroup_uniformity.compose` defines the final
verdict:

```text
drf_full =
  memory_drf and subgroup_uniformity_drf
```

The analysis deliberately separates memory DRF from subgroup well-definedness.
A kernel can have no memory race obligations and still fail the full verdict if
a subgroup or matrix operation is called under non-uniform control.

### Guarded Family Admission

The original MAP formalization can quantify over symbolic loop bounds and
array sizes, but implementation-level CUDA verification also needs launch and
template facts. The local ggml-cuda campaign records those facts as guarded
family contracts.

A family proof is admitted only when the generator has enough facts to create
fresh obligations:

```text
family F(theta)
guard G(theta)
obligations Q(F, G)

admit(F, G) =
  source_and_launch_facts_complete(F, G)
  and Q(F, G) is fresh
  and forall q in Q(F, G). classify(q) in { unsat, pre_solver_unsat }
```

The guard is part of the proof input. Example guard facts include positive
shape dimensions, template constants, block dimensions, grid dimensions, and
kernel-specific relations such as `C / H = HEAD_SIZE`.

`drf/lib/launch_contract.ml` and
`drf/lib/launch_contract_generator.ml` hold these contracts and candidate
carriers. The S447 host-template carrier is intentionally not a proof. The
carrier records that 54 families are blocked at source/header/template intake
and names the exact facts needed before obligations can be generated.

| Synchronization | Workgroup synchronization splits protocols. Synchronization does not appear inside the MAP syntax (PDF p. 7, Section 3.1). | Workgroup barriers still split phases. Subgroup barriers with memory semantics update subgroup phase keys without ordering different subgroups. | Thread identity | The semantics uses a thread id `i` and checks pairs of different threads (PDF p. 8, Figure 3; PDF p. 16, Section 4.3). | The two-thread model is preserved. Target configuration maps CUDA thread coordinates to subgroup identity. Missing target configuration is unsupported. |
| Memory access shape | Scalar array access `o[e]` (PDF p. 7, Figure 2). | Ordinary scalar accesses extracted from subgroup kernels. |
| Race predicate | Same array index, different threads, same trace, and at least one write (PDF p. 16, Section 4.3). | Same ordinary memory location, different projected tasks, conflicting modes, same workgroup phase, and no subgroup ordering. |
| Symbolic approximation | CI/DI classify whether symbolic variables can affect control or indexes. | Source inference | The paper infers MAPs from a synchronized source language and proves action-set soundness (PDF pp. 14-16, Sections 4.2-4.4). | The local source layer dispatches ordinary kernels to the existing path and subgroup/WMMA kernels to an explicit subgroup/matrix IR. | Mechanization status | The supplied paper reports a Coq mechanization of the stated theorems (PDF p. 16, Section 4.4). | The subgroup/matrix extension is an executable OCaml analysis and a specification note. The extension is not yet mechanized as a Coq theorem. |

## Additions Over Original Faial

The local implementation adds the following logical concepts.

1. Explicit subgroup target configuration.
   The analysis requires a CUDA-like x-contiguous subgroup mapping and a
   concrete subgroup size for subgroup/WMMA kernels.

2. Subgroup phase keys.
   Workgroup phases remain the outer race-checking unit. Subgroup operations
   with documented memory semantics refine ordering inside a workgroup phase
   without ordering different subgroups. Other recognized warp collectives are
   participation events and leave the memory phase unchanged.

3. Subgroup uniformity.
   Subgroup barriers, subgroup collectives, and matrix collectives must be
   reached under subgroup-uniform control. Memory DRF and uniformity compose
   into `drf_full`.

4. Matrix footprints.
   WMMA load/store operations are represented as cooperative rectangular
   footprints. Conflicts with other memory operations are still checked against
   those footprints.

5. Ordinary memory inside subgroup kernels.
   Scalar shared/global reads and writes in kernels that also contain subgroup
   or WMMA operations are recorded in the same subgroup-aware event stream.

6. Guarded family contracts.
   Template and launch facts are explicit proof inputs. A family-level row is
   only accepted after guarded facts generate fresh obligations that are proved
   unsat or discharged by a structural pre-solver rule.

7. Fail-closed unsupported boundary.
   Missing subgroup size, missing lane mapping, unresolved template facts,
   unsupported direct subgroup intrinsics, async operations without a modeled
   synchronization boundary, CUB, and inline assembly are not silently
   analyzed by the ordinary MAP path. Repeated
   memory-ordering barriers use the loop-aware protocol described above.

## Current Formal Boundary

The extension should be read as a local executable formalization rather than a
replacement for the original MAP theorem. The ordinary MAP path remains the
base case. The subgroup/matrix path adds a guarded proof obligation generator.
The accepted DRF statement for a supported subgroup kernel is:

```text
Given:
  explicit target configuration cfg
  accepted source extraction E
  accepted launch/template/shape guard G
  generated ordinary-memory obligations Q
  generated subgroup uniformity obligations U

If:
  every q in Q is unsat or structurally discharged
  and every u in U is subgroup-uniform

Then:
  the analyzed kernel is DRF with respect to the modeled ordinary memory
  events under cfg, E, and G.
```

The statement is intentionally guarded. Unsupported CUDA features, missing
source facts, missing launch facts, and unresolved template facts prevent
obligation generation rather than producing a DRF verdict.
