### Bug fix: scoping issue caused by function call inlining (Aug 10-11)

Fixed bug where function parameters clashed with caller context variables.
The root cause was a scoping issue. Function inlining was being done in `smt.ml` (where variable binding is unstructured) and needed to be done in `scoped.ml` (where variable binding *is* structured). Refactoring was needed to better encapsulate function inlining, so that the change is invisible to outside modules.

- Moved code (IMP) to the directory structure, library under `imp/src`, tests under `imp/test` ([a0456591](https://gitlab.com/umb-svl/faial/-/commit/a0456591c66304dc6914e5b2068e2d612d50cfd0))
- Fixed the order of argument/parameter assignment (was reversed) ([2b5e9763](https://gitlab.com/umb-svl/faial/-/commit/2b5e976335313242232c1c53c05df43dba0c6829))
- Moved some outstanding code relative to function inlining into `inline_calls` and converting IMP to Protocol into a separate file `compiler.ml` ([e7ebcf7d](https://gitlab.com/umb-svl/faial/-/commit/e7ebcf7d6b7cb7496e52952e2f1a3cf80e528c0b)) 
- Added a kernel to Scoped and made Compiler encapsulate function inlining  ([f3505ba9](https://gitlab.com/umb-svl/faial/-/commit/f3505ba942aaf3ffe8b8cdfb4aec4d9ea7ae19ff))
- Solution was to assign argument to parameters, then append the function code (making sure the binders are made distinct from the caller's context), and finally move the continuation to the "end" of the generated code ([eb1b5591](https://gitlab.com/umb-svl/faial/-/commit/eb1b5591ae4b7021ea841acc227e6d761d5cc3c7))
